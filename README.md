# FEG Analytics — Live Casino Floor Dashboard

A live "who is playing what right now" dashboard for the PSK casino demo, and the
activity banner that sits at the top of the casino tab.

**Zero dependencies, zero backend, no build step.** It is a static folder — point
any host at it, or run `node serve.mjs` locally.

---

## ⚠️ What is real and what is not

This distinction matters and is deliberately hard to lose:

**Real** — measured from a 31-day PSK casino event-log export (13,682 game
launches across 887 games):

- the game line-up and each game's provider
- every game's popularity *relative to the others* (top game = 5.17% of all play)
- the genuine hour-of-day rhythm (04:00 = 0.34×, 13:00 = 1.43×)
- the category mix (Slots 92.9%, Dice 3.5%, Blackjack 3.3%, Roulette 0.3%)

**Synthetic** — the absolute headcount. The export samples *top users only*
(~18 launches an hour across 887 games), so a literal reading gives "1 player",
which is equally untrue of PSK's real casino. The engine scales the real shape to
a production-like floor.

Every number shown is a **simulated demo value, not a real PSK figure.** The
disclaimer travels inside the JSON itself and is displayed on the dashboard, so a
figure cannot be lifted out of the pipeline and quietly lose the caveat.

## Running it

```bash
node serve.mjs      # then open http://localhost:5173
npm test            # 35 checks, no framework needed
```

Opening `index.html` straight from disk will not work — browsers block ES module
imports and `fetch` over `file://`. That is what `serve.mjs` is for.

## Deploying

**Live:** https://feganalytics.vercel.app

It is a static site — no build command, no install step. To redeploy:

```bash
vercel --prod
```

Pushing to GitHub does **not** redeploy on its own: Vercel's GitHub App has not been
granted access to this repo, so `vercel git connect` fails. Either run the command
above after pushing, or connect the repo once under
*Vercel → project → Settings → Git*, after which pushes deploy automatically.

Note that the long per-deployment URL (`feganalytics-<hash>-…vercel.app`) is behind
Vercel's deployment protection and will 302 to a login page. Share the short
canonical domain above instead — that one is public.

## How the numbers behave

The engine is a **pure function of the clock**. No stored state, no session seed.
That single decision buys several properties:

- **Every device agrees.** Two people opening the page at the same moment see
  identical numbers — it survives being handed to someone mid-demo.
- **History is recomputed, not recorded.** The 60-minute chart is derived by
  evaluating the engine at past instants, so it exactly matches what the page
  displayed at those moments.
- **No backend is needed** for any of the above.

Realism is enforced by tests rather than by eyeballing:

| Property | Why it matters |
|---|---|
| Smooth drift (value noise, not re-rolled randomness) | `174 → 177 → 172` reads as real; `174 → 41 → 300` does not |
| Stable ranking, occasional neighbour swaps | Real leaderboards do not reshuffle every 3 seconds |
| Measured hour curve, interpolated between hours | The floor never lurches at `:00` |
| Long tail thins out at quiet hours | 887 games are not all occupied at 4am |
| Sparkline agrees exactly with the count beside it | Both go through one code path, so they cannot diverge |

## Tuning for a demo

One dial, in `lib/liveCasinoMetrics.js`:

```js
export const PEAK_CONCURRENT_PLAYERS = 3200;
```

That is the floor's average-hour headcount. Raise it if the room should look busier.

The daily curve follows the **viewer's local hour**. The shape is the measured one
either way, but tracking local time means a mid-morning demo shows mid-morning
traffic instead of whatever UTC happens to be.

## Layout

```
lib/liveCasinoMetrics.js   the engine — pure, deterministic, browser + node
data/casinoCatalog.json    the measured catalog (built in the data-pipeline repo)
index.html                 dashboard markup and styles
app.js                     rendering, inline-SVG charts, hover layer
test/                      35 checks covering the realism invariants
serve.mjs                  zero-dependency local static server
```

The catalog is generated by `buildCasinoCatalog.ts` in the voice-agent repo, which
reads the raw event-log CSV and emits the measured shares, categories and hour
weights. Only its output is committed here.

## Chart colours

Data marks use `#0aa84c` and `#1475e1`. These are **validated**, not chosen by eye
— they pass the dark-mode lightness band, chroma floor, colour-blind separation
(ΔE 28.1 deutan) and contrast against the `#1a2c38` surface. Stake's brighter
`#00e701` sits outside the lightness band for data marks, so it is used only for
UI chrome such as the live indicator. Re-run the palette validator before changing
them.
